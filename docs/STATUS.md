# Status (2026-11-11)

- Runs only on the VPS: container `elder-brain-bot` (image `elder-brain-bot:local`, compose project `elder-brain-bot`, service `bot`), plain `docker compose` from the clone `/home/ubuntu/elder-brain-bot` on `palmer-main`. Deployed = the `palmer-main` tip. Secrets: `/etc/elder-brain-bot/.env`, owner `ubuntu`, mode 600 (root ownership breaks `env_file`).
- Deploy: merge into `palmer-main`, then on the VPS `git pull` and `docker compose up -d --build`, only on the operator's word. A docs-only change needs the pull and no rebuild (the bot's agent reads this repo live through the `/home/ubuntu` mount).
- Claude inside the container uses the operator's Claude Max login on the `claude-assistant_claude_auth` volume (`/root/.claude`); the bot DB is on `claude-assistant_claude_data` (`/app/data`). Both volumes keep their pre-rename names on purpose: renaming them needs a planned migration and a new login. Never switch it to an API key.
- Access is production-level by design: `/home/ubuntu`, `/etc/dokploy`, `/srv/lake` and `/etc/elder-brain-bot` mounted rw, the Docker socket, `APPROVED_DIRECTORY=/`.
- Rebuild trap: the container's `claude` CLI keeps its user-scope MCPs (`whatsapp`, `codex`) in `/root/.claude.json`, which a `--build` can wipe. Before a rebuild, copy that file into `/root/.claude/backups/`; after it, `docker exec elder-brain-bot claude mcp list` must show both. Restore `mcpServers` from the newest backup that contains both (choose by content, not size; the backups are dotfiles), or re-register them (commands in the operator's elder-brain wiki `wiki/projects/whatsapp-bridge.md`). The bot's own SDK sessions do not load these MCPs.
- The Mac checkout is for code and tests; nothing runs from it. Its `.venv` was created under an old path, so call tools as `.venv/bin/python -m ...`. Tests: `.venv/bin/python -m pytest -q -o addopts=""` (pytest-cov is not installed there).
